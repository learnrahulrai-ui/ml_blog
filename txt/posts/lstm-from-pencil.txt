  APPENDIX . LSTM FROM PENCIL
  RNN and LSTM From Scratch, Nothing But a Pencil

  PATH . APPENDIX -- LSTM From Pencil  (companion to Chapter 10; work it any time)
    <- back to:  [Chapter 10, Part 2: The Two-Memory Worker](the-two-memory-worker.txt)

  This page is a KATA: one clean walk through the RNN and the LSTM, by pencil, that you can
  redo on a blank sheet again and again until your hand knows it. No computer is needed at
  any step. It assumes nothing from the chapters -- every number is built here, in front of
  you, and recomputed where it is needed. The chapters draw the picture slowly; this page is
  the bare recitation, the thing you reproduce from memory at a 1950s desk.

  The setup, Faraday-plain: a pencil, sheets of graph paper, a few pockets in your coat. A
  pile of movie reviews, each with a tick -- liked (1) or not (0). The job: read a NEW
  review and tick it. We will walk ONE short review, "nolan ended", all the way through.


  ## The Desk: Words Into Numbers

  A clerk can only multiply NUMBERS. It cannot multiply the word "boring". So before any
  machine runs, every word is turned into a row of numbers -- looked up in a dictionary that
  holds one page per word:

    "nolan"  ->  [ 32 numbers ]      <- its row in the dictionary (call this nolan32)
    "ended"  ->  [ 32 numbers ]

  These 32 numbers per word are fixed once trained -- you flip to the word's page and copy
  them. Why 32 and not 1? Because one number per word could only say "leans good" or "leans
  bad", and a word like "not" leans neither way -- its whole job is to FLIP the next word.
  Thirty-two slots give a word room to be several things at once. The width 32 is a CHOICE
  (a knob), not a law.

  Everything below works on these 32-number rows. To keep the page honest we will often
  shrink 32 down to 1 or 3 numbers -- the arithmetic is identical, just shorter to write.


  ## Part 1: The RNN, By Pencil

  ON THE DESK -- one memory pocket and a frozen set of dials:

    memory       = [ 32 numbers ]    starts ALL ZEROS
    word-dial W  = a 32 x 32 grid     (one grid of dials for the incoming word)
    memory-dial U= a 32 x 32 grid     (one grid of dials for the old memory)
    nudge        = [ 32 numbers ]

  The dials W, U, nudge are FROZEN during a read-through -- the same dials are reused at every
  single word. That reuse is the whole idea, and it is why the textbook word is "recurrent":
  the one dial-set comes round again every word.

  GRID x ROW, BY PENCIL. The one step people trip on first: you cannot multiply a 32 x 32
  grid by a single number. A grid times a ROW of 32 works like this -- take row 1 of the
  grid, lay it against the word's 32 numbers, multiply pair-by-pair, and ADD the 32 products
  into ONE number. That is row 1's output. Row 2 against the same 32 -> number 2. Thirty-two
  rows -> 32 numbers, a brand-new row. A worked two-wide example (shrinking 32 to 2):

    grid = [ [1, 0],      word row = [ 5, 7 ]
             [0, 1] ]

    row 1 . [5,7] = 1x5 + 0x7 = 5
    row 2 . [5,7] = 0x5 + 1x7 = 7      ->  output [5, 7]

  (That grid -- ones on the diagonal -- is the "do-nothing" grid; it copies the row through.
  A real grid has other numbers and mixes the slots.) The ADD-up of products lives INSIDE
  each row; it is the only place anything is summed.

  THE ONE-WORD RECIPE (walk left to right, SAME dials every word):

    new memory = tanh(  W x word32   +   U x old memory   +   nudge  )
                        \_grid x row_/   \_grid x row_/      \_ 32 _/

  tanh is a fixed crusher: it bends any number into the band -1 to +1. By the numbers:
  tanh(0) = 0, tanh(1) ~ 0.76, tanh(2) ~ 0.96, tanh(5) ~ 1.0, tanh(-5) ~ -1.0. No dials, no
  learning -- one fixed curve, applied at the end.

  WALK "nolan ended":

    word "nolan": old memory = 0  ->  new memory = tanh( W x nolan32 + U x 0 + nudge )
                                                  (U x 0 is all zeros -- nothing behind word 1)
    word "ended": old memory = nolan's memory  ->  tanh( W x ended32 + U x oldmem + nudge )

  Same W, U, nudge both words. After the last word, the memory is a 32-number summary of the
  whole review, with order baked in. A final S-curve clerk reads that summary -> one chance,
  liked (1) or not (0).

    >> YOUR TURN  (two-wide, by hand)
       old memory = [0, 0] (first word). word32 = [1, 2]. W = the do-nothing grid
       [[1,0],[0,1]]. U = anything (old memory is zero so it drops out). nudge = [0, 0].
       tanh(1) ~ 0.76, tanh(2) ~ 0.96. New memory?

       check your slate:
         W x [1,2] = [1, 2] ;  U x [0,0] = [0, 0] ;  add nudge [0,0] -> [1, 2]
         tanh each -> [0.76, 0.96].   New memory ~ [0.76, 0.96].

  THE FLAW (a THEOREM, provable with a pencil). Look at what happens to the OLD memory: every
  word it is multiplied by U AND crushed through tanh. Crush, multiply, crush, multiply -- 90
  times over a 90-word review. A mark left by word 1 is mangled and re-squeezed ninety times,
  worn down toward nothing -- like a pencil mark rubbed ninety times. By word 90 the worker
  has effectively forgotten word 1. A long review's opening flip ("not ...") is lost. This
  fading is not a bug you can tune away; it follows from crushing the one memory every step.

    RNN memory:  tanh( U x old + ... )   -> mangled + crushed each word  -> FADES
    we want:     keep x old + add x new  -> scaled + added each word      -> SURVIVES


  ## Part 2: The LSTM, By Pencil

  The cure, in one line before we build it: stop crushing the long memory as it carries.
  Hold a memory that is only SCALED by a fraction and ADDED to -- never crushed on the way
  through -- so word 1 can ride all the way to word 90.

  ON THE DESK -- now TWO pockets:

    pocket A : memory A = [32]   the LONG VAULT.  Silent -- never read by any machine. Only
                                 scaled and added. Never crushed on the carry, so it CAN grow
                                 past 1 (it might read 5.0). Far-back marks survive here.
    pocket B : memory B = [32]   the SPOKEN readout.  THIS is what the machines read next
                                 word. It is a crushed, partial view of A. (Both start at 0.)

  THE FOUR MACHINES. Four little machines run side by side. EVERY one reads the same two raw
  things -- this word's nolan32 and memory B from last word -- and nothing else. Each has its
  OWN two grids (one for nolan32, one for B) and its own nudge:

    FRESH  = tanh(    Wf x nolan32 + Uf x B + bf )    -> the new content, range -1..+1
    keep   = sigmoid( Wk x nolan32 + Uk x B + bk )    -> 32 fractions, range 0..1
    admit  = sigmoid( Wa x nolan32 + Ua x B + ba )    -> 32 fractions, range 0..1
    show   = sigmoid( Ws x nolan32 + Us x B + bs )    -> 32 fractions, range 0..1

  ONE MACHINE -- TWO GRIDS INSIDE. Read the keep line again: nolan32 goes through grid Wk, B
  goes through a SEPARATE grid Uk, the two outputs ADD, the nudge joins, THEN the one squash.
  This is NOT a "word machine" feeding a "memory machine" -- both grids live inside the same
  one machine, and the add happens before the crush. All four follow this exact shape.

  Two crushers in play:
    tanh    -> a VALUE, can be + or -, range -1..+1
    sigmoid -> a FRACTION, "how much", a dimmer knob from 0 to 1.  sigmoid(0) = 0.5,
               sigmoid(2) ~ 0.88, sigmoid(-2) ~ 0.12, sigmoid(5) ~ 1.0, sigmoid(-5) ~ 0.

  Use them right: FRESH gets tanh (it carries content). The three votes get sigmoid (they
  carry a fraction). One crush each, at the end. Never tanh-then-sigmoid the same row.

  Notice FRESH is exactly Part 1's RNN recipe -- tanh of (word + old recent + nudge) -- reused
  whole. The LSTM does not throw the RNN away. It keeps it as ONE of four parts and wraps
  three dimmer knobs around it. LSTM = the RNN cell + three votes.

  THE COMBINE (every multiply is pair-by-pair, slot with slot -- NO summing across slots):

    new A = keep x (old A)   +   admit x FRESH
    new B = show x tanh(new A)

  In words: keep scales how much of the silent vault to hold; admit scales how much new
  content to let in; their sum is the new vault. Then show scales a tamed view of the vault
  into the spoken readout. memory A is touched for the FIRST time right here, in the combine
  -- no machine read it.

  WORKED, REAL NUMBERS (one slot; really 32, all the same way):

    old A = 5.0    FRESH = 0.6    keep = 0.9    admit = 0.2    show = 0.7

    new A = 0.9 x 5.0  +  0.2 x 0.6  =  4.5 + 0.12  =  4.62      <- held the vault, let in a touch
    new B = 0.7 x tanh(4.62)  =  0.7 x ~1.0  =  0.70             <- tame the vault, reveal part

  The vault went 5.0 -> 4.62: scaled by 0.9 and nudged up by 0.12, NEVER crushed. That is the
  whole escape from the fade -- a far-back mark can sit at 5.0 and still be there 90 words on.
  To SPEAK it, first tanh (4.62 -> ~1.0, tamed into -1..+1), then show (0.7) reveals 70% of
  it -> 0.70. A is the silent vault; B is what you say out loud about it.

  THREE SLOTS (each slot carries its OWN keep/admit/show -- element-wise, no summing):

    old A = [ 5.0 , -2.0 , 0.3 ]      FRESH = [ 0.6 , 0.8 , -0.1 ]
    keep  = [ 0.9 ,  0.5 , 1.0 ]      admit = [ 0.2 , 0.0 ,  0.9 ]
    show  = [ 0.7 ,  0.2 , 1.0 ]

    new A:  0.9x5.0  + 0.2x0.6  = 4.62
            0.5x-2.0 + 0.0x0.8  = -1.00       <- slot 2: kept half, admitted nothing
            1.0x0.3  + 0.9x-0.1 = 0.21
    new A = [ 4.62 , -1.00 , 0.21 ]

    tanh(new A) ~ [ 1.00 , -0.76 , 0.21 ]
    new B:  0.7x1.00 = 0.70 ,  0.2x-0.76 = -0.15 ,  1.0x0.21 = 0.21
    new B = [ 0.70 , -0.15 , 0.21 ]

  Put new A in pocket A, new B in pocket B, step to the next word, SAME dials. Repeat to the
  last word.

    >> YOUR TURN  (one slot, by hand)
       old A = 4.0, keep = 0.5, FRESH = 2.0, admit = 1.0, show = 1.0, tanh(new A) ~ 1.0.
       New A slot? New B slot?

       check your slate:
         new A = 0.5 x 4.0 + 1.0 x 2.0 = 2.0 + 2.0 = 4.0
         new B = 1.0 x tanh(4.0) ~ 1.0 x 1.0 = 1.0
       Kept half the old vault and admitted all the fresh content.

  THE TWO MEMORIES, PLAINLY:

    A = the raw long VAULT  (4.62, uncrushed, can grow big)   -- SILENT, no machine reads it
    B = the tamed partial READOUT of A  (0.70)                -- SPOKEN, every machine reads it

  WHY KEEP A IF NO MACHINE READS IT? Because the votes are APPLIED to it. A is the treasure;
  keep scales it, admit adds to it. The votes decide their fractions from today's word and B,
  then reach over and act ON A. Drop A and nothing carries far.

  SHOW'S DUAL ROLE. The new B that show builds lands in TWO places:
    1. NEXT word -- all four machines read it alongside the next word's row.
    2. LAST word -- the final clerk reads it for the liked/not verdict.
  The B the machines read each word was MADE by show the word before. show is the valve on
  the vault's mouth: hold silently (show low), speak only when it matters (show high).

  THE FINAL B IS THE WHOLE REVIEW. Walk "nolan ended": B after word 1 has seen only "nolan";
  B after word 2 has folded in BOTH words. The final B -- the one the clerk reads -- is the
  last one, carrying every word, not just the opener. Each B swallows the one before it.

  ENGINEERED, NOT DERIVED (a CHOICE, named out loud). The fade is a THEOREM you can prove with
  a pencil. The EXACT wiring -- two memories, these three votes, this combine -- was ENGINEERED
  by trial until it stopped the fade. A simpler cousin (the GRU) ties keep and admit together
  and merges the memories; it works about as well with fewer dials. Hold the mechanism --
  scale-and-add a silent long memory, gate it with dimmer knobs -- and treat the precise vote
  count as a historical accident, not a law.


  ## The Struggle Log (every snag, in one margin)

  The traps that catch everyone the first few times. Each is a sentence you correct out loud.

    "can't multiply a grid by one number"  -> grid x ROW: each grid-row dotted with the 32,
                                              summed to one number; 32 rows -> 32 numbers.
    "old A can't be 5.0 -- tanh caps it"    -> true for the RNN (crushed each word). FALSE for
                                              A: never crushed on the carry, so it CAN read 5.0.
    "is the combine a sum across slots?"    -> no. pair-by-pair, slot with slot. The only sum
                                              is inside a grid-row (the dot product).
    "a vote reads what it scales"           -> no. all four READ nolan32 + B; they are APPLIED
                                              to different targets (keep -> A, admit -> FRESH,
                                              show -> tanh(new A)).
    "two memories = two copies"             -> no. A is the silent vault; B is the spoken
                                              readout (show x tanh(A)). Different roles.
    "why keep A if unread?"                 -> the votes are applied TO A; A feeds B. Drop it
                                              and nothing carries far.
    "B is a grid/matrix"                    -> no. A and B are ROWS of 32 numbers. The grids
                                              (W, U) are the dials -- 32 x 32 each.
    "keep = 1 minus admit"                  -> no subtraction. keep and admit are two separate
                                              votes; both can be high at once. (The GRU ties
                                              them; this LSTM does not.)
    "word machine + memory machine"         -> one machine, two grids inside, added before the
                                              one crush. Four such machines, each its own dials.
    "show makes B once, done"               -> B is the output line: next word AND final clerk.
    "final B = the first word's"            -> final B = whole-review summary; each B swallows
                                              the one before it.
    "loud content must matter most"         -> no. a big FRESH can be admitted near 0. Loudness
                                              is the value; worth is the vote, judged apart.


  ## One Word, End to End (the recitation)

  The thing to reproduce from a blank sheet -- first word, so A and B are all zeros:

    1. flip to nolan's page -> nolan32 ;  pull A (all 0), pull B (all 0)
    2. run the four machines on (nolan32 + B):
         FRESH = tanh( Wf x nolan32 + Uf x B + bf )
         keep  = sigmoid( Wk x nolan32 + Uk x B + bk )
         admit = sigmoid( Wa x nolan32 + Ua x B + ba )
         show  = sigmoid( Ws x nolan32 + Us x B + bs )
    3. new A = keep x A + admit x FRESH        (A used here for the first time)
    4. new B = show x tanh(new A)
    5. put new A, new B back in the pockets. walk to "ended". SAME dials. repeat.
    6. last word: the final clerk reads the last B -> liked (1) or not (0).


  ## One Line Each

  RNN : one worker walks the review carrying ONE memory, rewritten-and-crushed every word
        with the same dials -- so far-back words FADE (a theorem).

  LSTM: TWO memories -- a silent uncrushed vault A and a spoken readout B; four machines
        (FRESH + keep/admit/show) read nolan32 + B; new A = keep x A + admit x FRESH grows the
        vault without crushing it (so far-back SURVIVES), new B = show x tanh(new A) speaks it
        out; same dials reused every word; the last B is the whole-review summary the clerk
        ticks. The fade is derived; the exact wiring is a choice.
